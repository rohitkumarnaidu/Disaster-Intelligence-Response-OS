## 1. APP OVERVIEW

**App name:** DRAXELYRA
**One-line description:** DRAXELYRA turns post-disaster drone/satellite imagery into evidence-backed cases, ranks them by an explainable priority score (not raw AI confidence), routes verified cases to accountable field response, and closes the loop with a permanent audit trail.

**Core problem it solves:** After a disaster, the bottleneck isn't detecting damage — it's everything after detection: deciding which findings are real, which ones matter most, who owns the response, and whether it actually got done. AI models produce candidate damage findings, but a confident detection on a low-stakes structure is not more urgent than a moderate-confidence finding next to a hospital. Today that judgment call lives in someone's head, a shared spreadsheet, or a WhatsApp thread — with no traceability. DRAXELYRA is the operational layer that sits between "the model found something" and "a verified, accountable action happened," built to be an evidence-to-action pipeline, not a detector demo.

**Target user:** Disaster management officers, GIS/assessment analysts, and field verification teams working with a national/state emergency management authority (e.g., NDEM/SDMA-style bodies) — plus, secondarily, an executive/coordinator who just needs the top-line picture. It is explicitly a complement to systems like NDEM, NDMA SACHET, and Copernicus EMS, not a replacement for any of them.

## 2. FULL FEATURE LIST

### Tier 1 — Core loop (must work end-to-end; this is what gets graded)
- Email/password auth with 6 seeded role accounts (Admin, Disaster Officer, Assessment Analyst, Field Verifier, Response Coordinator, Executive Viewer) and backend-enforced RBAC (never just hidden UI)
- Incident management: create/open/edit an incident, define its AOI on a map
- Demo Replay mode: "Load Demo Incident" and "Reset Demo" buttons that deterministically populate a full, internally-consistent scenario (imagery, detections, cases, reviews, tasks, one overdue task, one false positive, one completed field verification)
- Geospatial workspace: before/after imagery, critical-asset markers, candidate case markers, filters, layer toggles
- Case object as the spine of the data model — every case links imagery → detection → evidence → review → priority → task → field observation → outcome
- Evidence Review screen: before/after image comparison, confidence, model/version metadata, Confirm / Reject / Uncertain actions (reason required on Reject/Uncertain)
- Deterministic, explainable Priority Engine (backend-calculated, never LLM-calculated) with a visible factor-by-factor breakdown
- Priority Queue with filters (priority, severity, asset type, status, owner, SLA) and sortable columns
- Response Tasking: case → task, assign owner/team, due time, status transitions, SLA countdown, auto-escalation on breach
- Field Verification PWA: assigned tasks, GPS capture, photo/evidence upload, notes, confirm/reject, **explicit offline queue with a visible "Pending Sync" state and no silent overwrite on conflict**
- Outcome capture: every case ends in a stored, typed result (Resolved / Partially Resolved / False Positive / No Access / Escalated)
- Full audit trail: every status transition is logged with actor, timestamp, and reason, and is viewable per case
- Analytics page: backlog, confirmation rate, false-positive rate, avg. time-to-assess/verify/task, SLA compliance

### Tier 2 — Differentiators (these are what actually win the round; don't cut these for time)
- **Priority Ledger** UI — the priority score rendered as an itemized, monospace, receipt-style breakdown (`+25 critical facility`, `+22.5 severe change`, `~ +5.5 moderate confidence (55%)` etc.) so a judge can see in one glance that confidence is only one input among several
- **Confidence-vs-Priority scatter chart** on Analytics: every case plotted with model confidence on the X-axis and final priority on the Y-axis — visually proves the "a moderate-confidence hospital case can outrank a high-confidence low-stakes case" thesis without a word of explanation
- **DEMO REPLAY / MOCK INFERENCE / MODEL INFERENCE** badges shown on every detection so the app never overstates what's real vs. seeded
- Before/after imagery as a **draggable comparison slider**, not two static side-by-side images
- SLA countdown badges that visibly tick down and flip to "Overdue" + escalation badge in real time during the demo
- Case Timeline: a horizontal, stage-by-stage visual (Detected → Reviewed → Prioritized → Tasked → Field-Verified → Closed) with a "step through" control for the Demo Replay case — this is the single best 90-second demo moment
- A persistent one-line thesis strip in the Command Center header: *"Evidence → Explainable Priority → Owned Action → Verified Outcome"*

### Tier 3 — Nice-to-have (only after everything above is solid and tested)
- Weather context chip on Incident Detail (Open-Meteo, no key required)
- Real historical satellite tile overlay via NASA GIBS for authenticity (separate from the mock detection layer — labeled "reference imagery")
- CSV/PDF export of the Analytics summary
- Dark/light theme toggle (dark is the default and the one to polish; light is optional)
- Comment threads on a Case (lightweight, not a full chat system)

## 3. TECH STACK

Keep this a **single-language TypeScript stack** end to end — fastest to build and debug solo in Replit.

| Layer | Choice | Why |
|---|---|---|
| Frontend | React 18 + TypeScript + Vite | Fast HMR, standard Replit template |
| Styling | Tailwind CSS + a small custom design-token layer (see §5) | Fast, but must NOT ship default/unthemed component looks |
| Routing | React Router v6 | Standard, simple nested routes |
| Server state | TanStack Query | Caching, background refetch, avoids manual loading-state spaghetti |
| Client UI state | Zustand (tiny) or React Context | Selected incident, filters, sidebar state |
| Maps | MapLibre GL JS | Free, no vendor lock-in, works with plain GeoJSON |
| Charts | Recharts | Priority-vs-confidence scatter, SLA/analytics charts |
| Icons | lucide-react | Consistent line-icon set, no cartoon icon packs |
| Backend | Node.js + Express + TypeScript | One language across the stack; fast to scaffold in Replit |
| ORM | Drizzle ORM | Type-safe schema, plays well with Replit's built-in Postgres/Neon |
| Database | PostgreSQL (Replit-provisioned) | Geometry stored as GeoJSON in `jsonb` — no PostGIS dependency for MVP |
| Auth | express-session + connect-pg-simple (session store) + bcryptjs | Backend-enforced sessions, not just a frontend flag |

| Offline (Field PWA) | vite-plugin-pwa + Workbox + `idb` (IndexedDB wrapper) | Cache assigned tasks, queue unsynced observations |
| Testing | Vitest (unit) + Supertest (API integration) | Fast, TS-native |

## 5. UI & DESIGN INSTRUCTIONS

**The single biggest risk to this project is looking like a generic AI-generated dashboard. Follow this section literally.**

### Explicitly avoid these tells
- ❌ Warm cream background with a terracotta/clay accent and a big serif hero headline
- ❌ Near-pure-black background with one single bright acid-green or neon-vermilion accent
- ❌ Purple-to-blue gradient hero banners or gradient buttons
- ❌ Glassmorphism / frosted-blur cards used everywhere
- ❌ Default unstyled shadcn/Bootstrap look — every component must be re-skinned to the tokens below, not left at defaults
- ❌ Rounded-3xl corners on every card, stock illustration art (undraw-style), emoji used as icons
- ❌ Soft drop-shadows on every single element (use hairline borders + subtle elevation instead)

This is a **command-center / mission-control** product (think Palantir Foundry, Grafana, Linear, ArcGIS — not a marketing SaaS landing page). Density and precision are the aesthetic, not whitespace and friendliness.

### Design tokens
| Token | Value | Use |
|---|---|---|
| `--bg-base` | `#14171C` (charcoal, not pure black) | App background |
| `--bg-surface` | `#1C2027` | Cards, panels |
| `--bg-surface-raised` | `#242933` | Modals, popovers |
| `--border-hairline` | `#2A2F38` | All dividers/borders |
| `--text-primary` | `#E7E5E0` (off-white) | Body/headings |
| `--text-muted` | `#8B93A1` | Secondary text, labels |
| `--accent-gold` | `#C9A227` (muted/desaturated — never bright/neon) | Primary actions, active states, brand mark |
| `--status-success` | `#5B8C5B` (muted moss green) | Confirmed / resolved |
| `--status-warning` | `#C68A3B` (muted amber) | Needs review / SLA warning |

Spacing: strict 8px grid (4px only for icon-to-label gaps). Radius: 4–8px only, never fully rounded pills except tiny status dots. No `border-radius: 9999px` buttons.

### Typography
- **UI/body face:** Inter — for everything a user reads and clicks
- **Data/mono face:** JetBrains Mono (or IBM Plex Mono) — for case IDs, coordinates, timestamps, confidence %, SLA countdowns, and the Priority Ledger. This pairing (clean grotesque + monospace) is the deliberate signature: it makes the product feel like an instrument panel, not a website.
- Section labels use small-caps "eyebrow" style (e.g. `PRIORITY QUEUE`, letter-spaced, `--text-muted`) above page titles.
- Numbered pipeline stages (1 Imagery → 2 Assessment → 3 Priority → 4 Review → 5 Task → 6 Outcome) are the one place numbering is used — because that content genuinely is a sequence, not decoration.

### Signature element: the Priority Ledger
Render every case's priority score as an itemized monospace ledger, not a bare number:
```
PRIORITY  83
──────────────────────────────
+ Critical facility (Hospital)      +25.0
+ Severe observed change             +22.5
+ High population exposure           +18.0
+ Time-sensitive / access limited    +12.0
~ Moderate model confidence (55%)     +5.5
──────────────────────────────

```
This single component carries the whole product thesis — build it carefully, it is the thing judges will screenshot.

### Layout patterns
- **Command Center / Geospatial Assessment:** map-first, full-bleed canvas with a slide-over right panel for details (no modals for primary content)
- **Priority Queue / Tasks:** dense data tables (compact row height, monospace numeric columns), not padded card grids
- **Evidence Review:** a draggable before/after slider divider (real interaction, not decoration) with metadata in a fixed side panel
- **Field PWA:** single-column, large tap targets, bottom action bar — this is the one screen designed mobile-first, everything else is desktop-first with responsive fallbacks

### Motion — spend it in one place
- Skeleton loaders for data fetches (quiet, not shimmering rainbow)
- One real orchestrated moment: the Case Timeline "step through" animation on the Demo Replay page
- Respect `prefers-reduced-motion` everywhere else. No confetti, no bouncing icons, no page-load fade-ins on every element.

### Copy voice
Active voice, plain language, named by what the user does: "Confirm finding" not "Submit detection," "Assign task" not "Create tasking record." Empty states are instructions, not apologies: *"No cases need review yet — cases will appear here once imagery finishes processing."* Errors state what happened and what to do: *"Imagery processing failed — retry the job from Data/Imagery."*


### Deterministic priority formula (implement exactly — never route this through an LLM)
```
severityScore     : No damage=0 · Minor=20 · Moderate=45 · Severe=75 · Destroyed=100 · Uncertain=35
criticalityScore  : Hospital/Emergency=100 · Bridge=85 · Gov/Utility=75 · School=70 · Residential=40 · Commercial=30 · Other=15
exposureScore     : High-density zone=90 · Medium=55 · Low=20   (each CriticalAsset is tagged with a zone tier in seed data)
urgencyScore      : clamp(100 − (hoursSinceIncidentStart / 72 × 100), 0, 100) + (accessConstrained ? 20 : 0), capped at 100
confidenceInput   : confidence(0–1) × 100

priorityScore = round(
  0.30 × severityScore +
  0.25 × criticalityScore +
  0.20 × exposureScore +
  0.15 × urgencyScore +
  0.10 × confidenceInput
)
```
**Worked example (use this as the canonical Demo Replay hero case):** Severe damage near a hospital, high-exposure zone, access constrained, only 55% model confidence →
`0.30×75 + 0.25×100 + 0.20×90 + 0.15×80 + 0.10×55 = 22.5+25+18+12+5.5 = 83`. A moderate-confidence finding still lands in the top priority tier — this is the entire product thesis, made concrete.

**SLA bands (demo/configurable — label them as such, not as official standards):** priority ≥ 75 → 30-minute response target · 45–74 → 2 hours · <45 → 8 hours. Escalate and badge "Overdue" automatically when `dueAt` passes without a status update.

### Free/public APIs (exact endpoints, no paid keys required)
| API | Endpoint | Use | Notes |
|---|---|---|---|
| **Overpass API** (OpenStreetMap) | `POST https://overpass-api.de/api/interpreter` | One-time seed: pull real hospitals/schools/bridges inside the AOI as `CriticalAsset` rows | Body is raw Overpass QL, e.g. `[out:json];node["amenity"="hospital"](13.00,80.15,13.15,80.30);out;` — no key, but cache results, don't poll live |

| **NASA GIBS** (optional) | `https://gibs.earthdata.nasa.gov/wmts/epsg4326/best/{Layer}/default/{Date}/{TileMatrixSet}/{z}/{y}/{x}.jpg` | Real public-domain MODIS/VIIRS imagery tile for a real historical date, as a "reference imagery" backdrop layer (kept separate from the mock detection layer) | No key; free/public domain; optional/stretch |
